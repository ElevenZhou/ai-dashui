0数据这块：开源的是代码，不是数据

项目是开源的，但数据还是要买的对吧？
对。而且是这套系统里唯一必须持续付费、且无法自建的部分。

GitHub 上那些套利项目，开源的都只是框架和逻辑：怎么取数、怎么匹配同一场赛事、怎么算套利、怎么分配注额、怎么推送。它们没有一个自带数据——每个项目打开 .env 第一件事就是让你填 API key。

原因是赔率流本身是一门生意：

  • 实时赔率是商业数据。平博（Pinnacle）这类 sharp 庄家的赔率变动就是市场信号，数据商靠转售它们赚钱，不可能免费放出来。
  • 官方渠道已经关死。平博 2025-07-23 起关闭公开 API 注册，只剩商业协议客户。想拿平博数据，要么买第三方数据商，要么走 PS3838 白标 + broker 开户。
  • 免费额度只够测试。见下表，所有免费档的配额连盯一场比赛都不够，更别说全天候扫货。

成本结构要认清

这套系统的钱分两块：代码成本 ≈ 0（开源项目随便改），数据成本 = 固定月费（$89–500/月）。想省钱只能砍数据源等级，砍不了这一项。反过来，先花 $89–100 买最低档验证信号质量，比一开始就上 $500 的聚合套餐理性得多。

顺带说清另一件事：数据商卖的只是数据，不是下单能力。买了 PinnAPI，你还是得自己去平博页面点。要实现全自动下单，得走 PS3838 API（平博白标，经 broker 开户），那是另一条独立的账户通道，不是"再买个 API 套餐"能解决的。

三个截图调研时没有覆盖到的信息

  1. 平博官方 API 已于 2025-07-23 关闭公开注册 不再有开放的 developer signup，官方渠道只剩商业数据协议客户。平博数据的现实获取路径只剩两条：第三方数据商（PinnAPI / Pinnwire），或 PS3838（平博自家白标，经 broker 如 Asianconnect 开户，API 同源同端点）。
  2. Pinnwire 是比 PinnAPI 更便宜的平博数据备选 $89/月 vs $100–300/月，且提供免注册的 demo key（key=demo），可以先用它验证端到端延迟，再决定要不要付 PinnAPI 的钱。
  3. Goalserve / Sportradar 只卖赛事数据，不卖赔率 这两家是比分、赛程、球员统计的老牌供应商。如果你的系统只需要"赛事框架 + 平博赔率"，用平博专线 + 免费赛程 API 就够，不必买它们的套餐。

避坑

付费前必查

不要买 OddsJam API 等美制聚合商。宣传极快，但不含 Pinnacle 和 Bet365 的核心盘口。付款前必须让对方提供支持的博彩公司列表（Bookmakers List），逐家核对。

延迟的真实算法

所有"扫货"速度都按端到端计：数据商节点 → 你的服务器 → 通知到达手机 → 你完成点击。数据商的 20–50ms 只是第一段，通知链路（Telegram / WebSocket）通常再要 100–500ms，手动点击又是秒级。想真正"快"，最终都得走到自动下单。

2扫货系统架构：六层

截图里 Gemini 的回答在"二、扫货系统的核心架构设计建议"处被截断。以下是补全版本，并融合了本次调研中开源项目验证过的做法。

信号主链路 + 旁路数据落库。风控层贯穿全程，图中省略。

① 接入层：能用推就别用拉

  • 首选 SSE（Server-Sent Events）：比 WebSocket 简单、断线自动重连、穿透 CDN 友好。PinnAPI 的 odds-drop 就是 SSE，min_drop=7 表示只推送跌幅 ≥7% 的变动，过滤在服务端完成，客户端代码极薄。
  • 如果只能 REST（免费档），轮询间隔不低于 90 秒，且只在开赛前 1–2 小时窗口轮询——赔率变动最密集的时段才值得花配额。
  • 多数据源时各自独立长连接，一个源挂掉不影响其他源。

② 信号层：少即是多

  • 阈值过滤放服务端，本地只做轻量二次确认。
  • 去重与冷却：同一赛事 + 同一市场（如 1X2 主胜）的信号 N 秒内只报一次，防止连续小幅跳动刷屏。
  • 回跳过滤：prematch 流用 recheck=N 参数，让数据商对每个 alert 持留 N 秒复核，过滤"假跌破"。
  • 按项目分频道：足球 / 网球 / 篮球各一个 Telegram 频道，避免互相干扰。

③ 决策层：信号里直接带答案

  • 用数据商的 no-vig 公允价（Pinnwire 的 nvp），或本地用 power / shin 方法 devig，算出真实概率。
  • EV = 目标盘赔率 × 真实概率 − 1，EV > 0 才推送。
  • 注额用分数 Kelly，开源项目通用做法是 30% 全 Kelly，控制方差。
  • 消息里直接给出赛事、市场、当前赔率、建议注额、预期收益——手工扫货时，让人现算就是浪费钱。

④ 执行层：让"点到"这一步最短

  • Telegram 消息内嵌平博投注页深链接（带 eventId / lineId），点击直达投注单，赔率已锁在链接参数里。
  • 桌面端加声音 + 系统弹窗（架构参考 PROPPR 的多 bot 分发）。
  • 浏览器保持平博登录态；注额预设（100 / 500 / 1000）减少输入。
  • 进阶（真正的速度）：ps3838api 提供完整的 Python 封装——查余额、拉 fixtures/odds、place_straight_bet 下单、get_bets 查状态，可直接当执行层 SDK。

⑤ 数据层与风控层

  • SQLite 快照：每条信号 + 当时赔率落一张表（时间、赛事、市场、from/to、EV、注额、是否出手、赛后结果）。两周就能统计出哪类信号真能打到、实际 edge 多少、哪些联赛值得盯。
  • 限额跟踪：平博对盈利账户会限额，系统要记录每个账号各市场的最大可下注额，超限信号直接丢弃。
  • 频率控制与熔断：每小时出手上限，防止信号风暴下重仓；接口连续报错或赔率明显异常（如 1.01）时自动暂停告警。

最小可行组合（MVP，一周可落地）

PinnAPI SSE（min_drop=5）
  → Python asyncio 消费者
    → 本地 EV + 30% Kelly 计算
      → Telegram Bot 消息（赛事 / 赔率 / 建议注额 / 深链接）
        → SQLite 快照落库

只依赖一个 API key 和一个 Telegram bot token，代码量约 300–500 行。验证信号质量后再升级 WebSocket 全量流 + PS3838 自动下单。

怎么选

抄架构 → danielcardeenas/surebet；抄"平博监控 → 执行"闭环 → Akinlua/sportybet；抄生产级工程 → Jayzinq/PROPPR；要自动下单 → ps3838api + 上面任一监控项目。

4落地路线：三步，每步可回退

  1. 本周 · 验证信号质量 买 PinnAPI 月付 → 接 SSE odds-drop → 按 MVP 搭起来 → 手工扫货两周。月付随时可停，这一步风险最低。
  2. 验证后 · 扩展 Value 检测 加 OddsPapi 或 The Odds API WebSocket 档 → 做跨平台差价检测。此时你已经有本地快照数据，能判断多源是否值得那份钱。
  3. 放大 · 自动化执行 Asianconnect 开 broker 户拿 PS3838 API → 用 ps3838api 把执行层改成自动下单 → 风控与限额层跟上。不开户也不影响前两步。

5合规提示

免责声明

体育博彩与套利在多数司法辖区（包括中国大陆）属于违法或严格监管行为，且多数平台的服务条款禁止自动化接入。本报告及所列开源项目仅供技术研究与学习参考。实盘前请自行确认所在地法规与平台条款，风险自担。
